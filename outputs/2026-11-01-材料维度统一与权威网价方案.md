# 材料维度统一与权威网价方案（2026-11-01）

## 一、现状盘点（先说结论）

工作区里那批未提交改动（V22–V25 迁移 + `BatchMaterialService` / `MaterialReconcileService` / `MaterialQuoteBindingService` + `MaterialIdentityTest`）**就是一版「材料维度统一」的 P0 影子实现**（注释标注 2026-10-29/30），方向与本需求高度一致，且几个关键设计决策是对的：

| 已有设计 | 评价 |
|---|---|
| `batch_materials`：一个批次一种材料一行，五维身份（大类/牌号/直径/定尺/产地），两级键 + 组内唯一非空值回填 | ✅ 正确解决「采购单不写产地、送货单写了」 |
| `batch_material_aliases`：AI 判同按「写法」缓存（raw_key），同写法只问一次 AI | ✅ 成本可控、可解释 |
| AI 判同只能「选已有材料 M1/M2 或 new」，五维过后端校验（牌号正则/直径纯数字），patch 只补空缺 | ✅ 防幻觉 |
| 材料级网价绑定（quote_*），采购/送货共用一条绑定；AI 从当日候选里「选」，价格一律从行情表取 | ✅ 符合「价格是事实，模型不生成」 |
| 行情候选收窄：按取价日（≤最近行情日）取当日行，LIMIT 400；AI 输出必须落在候选集 | ✅ 回应「不能全库一股脑给 AI」 |
| auto/manual 双来源：人工绑定永不覆盖，auto 只在重跑时刷新 | ✅ 钉住哲学一致 |

**但有三个致命缺口：**

1. **全是死代码**：`reconcileBatch` / `bindBatch` 没有任何外部调用方——单据确认流程、Controller、前端全都没接。影子层一次都不会跑。
2. **只写不读**：送货单锁价（`DeliveryNetPriceService` + `document_item_market_mappings`）、采购成本（`PurchaseCostResolver` 双索引+直径桶猜测）、台账，全部还是旧的按行匹配路径。需求 3 的「改一处」没有落地。
3. **权威网价完全没有**：需求 4 的截图更新链路不存在。

## 二、方案总览

```
采购单明细行 ──┐
              ├─ AI 判同（按写法缓存）→ 批次材料行 batch_materials ←─ AI 从当日候选中选 ── 行情库 market_quotes
送货单明细行 ──┘                        （身份五维 + 共享参数）                        （爬取 gtgqw + 权威截图 mysteel）
```

数据分三类，存放位置严格分开：

- **事实（输入）**：单据原始字段（material_name/spec/origin/数量/金额）与采购价，留在单据明细行，**一字不动**。采购价唯一事实在采购行，材料行通过 `supply_item_id` 引用。
- **参数（共享，改一处）**：网价绑定 `quote_*`、定价口径 `pricing_mode/uplift/margin`、人工销售价，全部放 `batch_materials`。采购侧和销售侧都读这一行。
- **结果（输出）**：估算售价、毛利，一律读时现算，不落库。

用你给的四张真实单据验证五维身份：

| 单据 | 写法 | 归一身份 |
|---|---|---|
| 送货单 | 螺纹钢HRB400 / 25*9 / 品牌中天 | 螺纹钢\|HRB400\|25\|9\|中天 |
| 提货单 | 25螺纹钢 9m / 无产地 | 螺纹钢\|?\|25\|9\|? → 组内回填成中天 |
| 找钢网销售单 | 三级螺纹钢 / 12*9 / 中天 | 螺纹钢\|HRB400\|12\|9\|中天（三级=HRB400 由 AI 判） |
| 我的钢铁截图 | Φ12-14 HRB400 中天 3270 | 范围规格，Φ12、Φ14 都命中它（现有 range 匹配已支持） |

## 三、对四个需求的逐条回应

### 需求 1：匹配交给 AI，不靠正则

采用已有方案的分工：**AI 是主路径，规则只是降级**（模型未配置/超时/积分不足时保证链路不断，不会因降级把 AI 已判定的写法重新拆开）。AI 判同的输入不只材料名，还包括单据侧信息（日期、往来单位、数量）——人就是靠这些把两侧对上的。

### 需求 2：网价匹配优化与候选收窄

现有三层收窄已成立，行情库变大不影响：

1. **日期收窄**：取价日 = 采购侧最早单据日，≤该日最近的有行情日（一天一个价）；
2. **候选收窄**：只取当日的行情行（单日几十到几百条，LIMIT 400），**历史数据再多也不进 prompt**；
3. **输出约束**：AI 返回的 productCode+specName 必须落在候选集，落不进去一律丢弃——模型只能选、不能造。

成本上三道闸：按写法缓存（aliases）、绑定钉住（auto 不重复问，重跑才刷新）、按取价日合并（一批次一般一次调用）。

**待补强的两点：**
- **候选可再收窄一级**：目前当日候选不分产品全给 AI；可先用 `MaterialIdentity` 规则预判产品大类，只给对应产品的候选（螺纹钢材料不给盘螺/高线的候选），prompt 更小、准确率更高。AI 预判不出产品时退回全量候选。
- **缺人工兜底 UI**：AI 未命中/规则降级的材料要能被人一眼看到并手动指定（manual 通道后端已有，缺 API + 页面）。

### 需求 3：原始字段不动，共享数据改一处

- 明细行原始字段不动，只在确认后回写 `material_id`（可逆，随时可整批重建）；
- 共享参数集中在 `batch_materials`：改网价绑定/定价口径，只改材料行，两侧同时生效；
- 采购价不改在材料行上——它是事实，改价必须改采购行（材料清单页提供「改采购单价」入口，写回采购行，材料行只引用），避免出现第二份事实。

**消费切换（P1 的核心工作量）：**

| 消费方 | 现状 | 切换后 |
|---|---|---|
| 送货单锁价 | 按行匹配 → `document_item_market_mappings` | 读材料行 `quote_*` 绑定取价；行级 mapping 保留过渡，稳定后废弃 |
| 采购成本 | `PurchaseCostResolver` 大类双索引+直径桶猜测 | 直接读材料行 `supply_item_id`，猜测逻辑退役 |
| 台账/采购毛利率 | 现算 | 数据源换成材料层，列序/表头/KPI 不变 |
| 送货单先行行 | 禁止借 `purchaseQuantity`（既有坑） | 材料层取数天然绕开，回归测试覆盖 |

### 需求 4：权威网价截图 → 全链路更新

V6 已预留 `source`（gtgqw/mysteel）且唯一键含 source+origin，天然支持多源，不需要动表结构。

**链路设计：**

1. **入口**：聊天上传截图（与单据识别同一 `ChatService.upload` 通道），意图识别增加「行情截图」一类（区别于采购/送货单据）；
2. **解析**：AI 视觉抽表 → 结构化行（城市/日期/品类/规格/牌号/钢厂/价格/涨跌）→ **预览确认后**才落库（截图识别可能不准，必须人过一眼）；
3. **落库**：upsert `market_quotes`，`source='mysteel'`；与爬取价共存（同日同产品同规格同城市同产地时两条都在）；
4. **取价优先级**：材料绑定命中多源时**权威价优先**（推荐），爬取价保留可回溯；不直接覆盖爬取数据；
5. **全链路刷新**：权威价落库后，找出「绑定命中该行情的材料」所在批次 → `bindBatch(refreshAuto=true)` 重绑 → `resyncDeliverySales` 重算销售 → 台账随之更新。

**拍板点**：已对账/已锁定价格的批次要不要自动重算？推荐：**未对账批次自动重算，已对账批次只提示、由人确认后重跑**——否则已确认的数字随一次截图静默漂移，违反「钉住」原则。

## 四、分期实施

| 阶段 | 内容 | 交付物 |
|---|---|---|
| **P1 接线** | 单据确认/编辑流程接 `reconcileBatch → rebuild → bindBatch`；异常全吞（影子层不拖垮主流程） | 材料层开始真实运行 |
| **P2 消费切换** | 锁价/成本/台账切材料层；候选按产品收窄；材料清单 API（含 AI 未命中标记）+ 人工绑定/改价 UI | 「改一处、两侧生效」可用 |
| **P3 权威网价** | 聊天行情截图识别 → 预览确认 → 落库（source=mysteel）→ 受影响批次刷新 | 需求 4 全链路 |
| **P4 清理** | 旧行级匹配降级为纯兜底；`document_item_market_mappings` 废弃评估；（可选）跨批次全局别名缓存 | 减债 |

历史批次不回填：材料层只对之后确认/重跑的批次生效，存量靠手动重跑校准（与现有口径一致）。
