# AI 对账系统 · 业务理解确认与架构修正方案

> 2026-09-13 · 基于：全量代码调查（backend + web + mini-new）+ 两份参考 Excel（《2026年葭安销售账单》＝台账参考、《36班项目钢筋（葭安）单独对账单》＝对账单参考）
>
> 结论先行：你对系统的问题判断**属实**，送货单的语义在代码里被明确建模为「供货单的到货确认」，销售侧（卖货给下游）在送货维度上没有实体。下面是完整的理解报告与修正方案。

## 一、业务全貌（我的理解，请校验）

**商业模式**：直运贸易。找到下游客户（如浙江众安建设）→ 承接项目供料（如九堡单元 36 班小学钢筋）→ 向上游供应商（如上海找钢网/兴泰物资）采购 → 货物**从供应商直运到客户工地**（不落地）→ 成本 = 采购价 + 运费，收入 = 销售价（网价 + 上浮），利润 = 单价差。

```
【上游采购链路】                          【运费支线】
供货单 ─→ 请款单 ─→ 付款短信 ─→ 进项发票    运费条目(送货单/运输单) ─→ 运费付款 ─→ 进项发票(9%)
(供应商,13%)                (材料13%/运输9%)
        │
        │ 直运
        ▼
【下游销售链路】
送货单(发货给客户) ─→ 收款短信 ─→ 销项发票
```

**核心抽象（本次确认的最大变化）**：
- **批次 = 一张供货单 = 一个采购批次**。批次内所有单据（送货单、请款、付款、发票、收款）都默认归属该批次，**不存在「选择属于哪张供货单/送货单」的操作**。
- **送货单 = 销售侧发货凭证**（发往下游客户的发货单），一个批次可有多张送货单（多日期发货），材料条目和总量应能与供货单对上。
- **对账台账**：给管理方看的「批次级」账——采购金额/运费/请款/付款/进项发票 vs 销售金额/开票/收款/毛利。材料明细只是辅助显示。
- **对账单**：给客户看的「送货单级」账——按日期范围导出，日期内每张送货单的材料/数量/网价/单价/金额逐日归纳，附发货单照片。

**与参考 Excel 的对应关系**：
- 《2026年葭安销售账单.xlsx》= 对账台账的人工版：每条记录 = 一个采购批次（订货单号 JAKJ20260106-1），左块采购明细（材料行+运输行）+ 进项票/付款流水，右块销售（订货单号/销售总额/开票/收款/毛利/毛利率）。我们的台账是它的丰富版。
- 《36班项目钢筋（葭安）单独对账单.xls》= 对账单的人工版：8 个 sheet = 8 个对账周期，每个 sheet 内按送货日期归纳材料明细，**单价 = 网价 + 30**，发货单列放照片。

## 二、问题确认：送货单当前语义错误（代码证据）

当前实现把送货单建模为「**对供货单的送货**（到货确认 + 可选配送运费）」，具体证据：

| # | 位置 | 证据 |
|---|------|------|
| 1 | `LedgerService.findTargetLedger` (L390) | 批次内无台账时直接报错：**「当前批次还没有采购台账，请先确认供货单」**——送货单必须依赖供货单先入库 |
| 2 | `LedgerService.applyContribution` (L286) | `case "delivery_note"` 把送货单金额记入 **`freight`（运输费用）**，而非销售额 |
| 3 | `DocumentService.extractAmount` (L1720) | 送货单只提取 `transportFee/freight`，注释明确「不能回退到 totalAmount，否则会把货物金额误记成运费」——**货款金额被系统性丢弃** |
| 4 | `ChatAiService` prompt (L229) | AI 识别定义：「送货单/出库单/配送单：主要用于确认材料**实际到货**数量/重量」 |
| 5 | `LedgerExportService.summarizeDelivery` (L383) | 送货单明细按**供货单**的 materialKey 累加，产出「待送达/部分送达/已送达」——是采购履约核对视角 |
| 6 | `DocumentService.expenseCandidates` (L1422) | 送货单（带金额）被列为**运输费用**的挂靠候选（与运输单并列）——再次确认它是成本侧凭证 |

**影响**：销售侧完全缺失——`sales_amount` 只能人工在批次摘要里填；送货单上的销售单价、客户、发货单号等信息没有被结构化提取；对账单（基于送货单）无从导出。

## 三、新架构：单据角色重定义

### 3.1 单据角色对照表

| 单据 | 旧语义（现状） | 新语义（目标） | 台账归属 |
|------|--------------|--------------|---------|
| **供货单** supply_order | 采购凭证，确认后建台账骨架 | **不变**：采购侧主单据，确认后写入 materials（采购材料基准）+ 台账骨架 | 采购与付款 |
| **送货单** delivery_note | 供货单的到货确认 + 运费 | **销售侧发货单**：客户、日期、材料明细（名称/规格/数量/**销售单价**/金额）、**运费（必填）**、发货单图片 | 销售与收款 + 运输费用行 |
| 运输单 transport_note | 运费凭证 | 不变（送货单自带运费后，独立运输单仍兼容） | 运输费用行 |
| 请款单 / 付款短信 / 进项发票 | 挂供货单或运费单据 | 不变 | 采购与付款 |
| 收款短信 / 销项发票 | 挂批次 | 不变（收款金额可与送货单金额核对） | 销售与收款 |

### 3.2 批次内操作模型

- 建立批次后，批次 = 一张供货单。**所有导入操作都不再选择归属单据**：上传 → AI 识别类型 → 归入当前批次。
- **导入顺序无关**：
  - 先导供货单 → 建 materials + 台账骨架（采购金额行）；
  - 先导送货单 → 也可先构建台账骨架（材料行、运输费用行），采购金额列留待供货单补齐；供货单后到时自动归位（现有 `replayWaitingSupplements` 的方向反过来也成立）。
- **送货单确认时的必填校验**：若 AI 识别结果中没有运费信息，**强制要求补填运费**（金额 + 可选承运单位）后才允许确认入库。运费因此天然挂在送货单上，成为运输费用行的直接来源（独立运输单仍可追加）。

### 3.3 材料匹配机制（供货单 ↔ 送货单）

- 供货单材料（materials 表）是批次的采购基准；送货单明细是发货事实。
- 两者按「名称 + 规格」匹配，**不要求逐字符一致**：规格归一化（`Φ12×9M` ≈ `φ12*9m`，`φ6盘螺` ≈ `φ6.5盘螺` 类似处理）+ 名称同义 + 数量级校验；复用现有 `MaterialMarketMatchService` 的分层策略思想（精确 → 归一模糊 → AI 兜底）。
- 匹配结果用于：① 台账材料行显示实际发货量与发货状态；② 对账单导出时核对供货量；③ 差异（多发/少发/匹配不上）在台账上标出待处理，不阻断流程。
- 批次内多张送货单按日期累加，与供货单总量核对（总量守恒即可，不苛求逐条一致）。

### 3.4 台账骨架的行结构（重申）

一行 = 一个「供货单材料分组」（materialKey 聚合），批次内另有一条运输费用行（所有送货单运费 + 运输单合并）；销售/收款列在批次组上合并显示。这条结构**不变**，只是数据来源修正：销售金额来自送货单明细金额合计（自动），而非人工填写。

### 4.3 台账「不太关心具体材料」的口径确认

你的第 3 点与现状一致：材料行存在的意义是把「采购了什么、送了什么」显示清楚供核对，**财务计算全部在批次级完成**（采购额、运费、请款、付款、发票、销售额、开票、收款、毛利、毛利率）。如果希望更极简，材料行可以折叠成一行「材料合计 N 项 / 总量 X 吨」，点击展开——这个留给你拍板（见问题清单 #2）。

## 五、对账单导出（基于送货单，你的第 5、6 点）

### 5.1 参考对账单结构（已完整解析，结论：**非常适合做模板**）

《36班项目钢筋（葭安）单独对账单.xls》：8 个 sheet = 8 个对账周期，命名如「7.22钢筋36班」「8.24--8.31钢筋」。每个 sheet 骨架固定（12 列 A–L）：

```
行1  标题：浙江众安建设集团有限公司（钢筋）对账单
行2  项目名称：九堡单元…36班小学        日期：2026年9月1日--2026年9月7日   ← 动态
行3  合同名称：钢筋
行4  供应商名称：杭州葭安科技有限公司                                          ← 我方
行5  「材料明细」横幅
行6  表头：序号│名称│规格│数量│网价│上浮│单价│单位│金额(元)│日期│发货单│备注
行7+ 明细行：同一天的多行，日期列(J)纵向合并；K列=发货单照片占位
合计  「合计：」行：数量 SUM、金额 SUM，其余填「/」
尾部  4 行汇总指标（本次供应量/累计供应量/本次供货金额/累计供货金额/本次支付/累计已支付）
      + 备注行 + 6 处签章区 + 法律声明（固定不动）
```

公式痕迹：`F=G-E`（上浮=单价−网价）、`I=D*G`（金额=数量×单价）、合计行 SUM——**所有行均满足 单价 = 网价 + 30**。

### 5.2 导出方案

- **入口**：台账页/项目页新增「导出对账单」→ 弹窗选择：项目（批次范围）、**日期范围**、客户（默认项目客户）。
- **数据源**：日期范围内的**送货单**，按送货日期分组归纳；一个导出请求生成一个 sheet（可多次导出拼成多周期工作簿）。
- **实现**：后端新增 `StatementExportService`（POI）。**需要你提供对账单空模板**（.xls/.xlsx 均可），填充流程：
  1. 复制模板骨架（标题/表头/尾部签章区原样保留）；
  2. 替换 I2 周期日期文本；
  3. 在表头与合计行之间插入 N 行明细：序号、名称、规格、数量、**网价**（来自行情匹配，见第六节）、上浮（默认 30）、单价（=网价+上浮，可改）、金额（=数量×单价，写公式）、日期、备注（产地）；
  4. 同日期多行对 J 列纵向合并；
  5. **发货单列（K）**：写入对应送货单的原始图片——原始件已存 COS（`/api/documents/{id}/access-url` 可取），POI `addPicture` 插入 K 列合并区；取不到图片时降级写送货单编号文本；
  6. 合计行 SUM 公式；尾部汇总区：本次值取合计，累计值按项目维度累加历史（需在系统内维护「累计供应量/累计供货金额/累计支付」的项目级滚动值，新增字段或实时重算历史送货单）。
- **sheet 命名**：`M.D--M.D钢筋` / 单日 `M.D钢筋`，与人工版习惯一致。

## 六、网价（行情价格）与匹配逻辑（你的第 7 点）

### 6.1 现状核实

- **历史日期行情价：有存**。`market_quotes` 表唯一键为 `(quote_date, source, product_code, spec_name, city, origin)`——**按日期逐日 upsert，历史价格持久保留**。爬虫（钢易网 gtgqw，`MarketCrawlerService`）按文章日期入库，城市默认杭州（`app.crawl-cities:杭州`），调度为启动全量一次 + 每 5 小时增量。⚠️ 需上线验证一点：**历史覆盖深度**（爬虫启动全量能回溯到多久之前，查 `min(quote_date)` 即知）。
- **缺口**：匹配服务 `MaterialMarketMatchService` 目前用 `latestQuoteDate()`（全表最新一天）做匹配——**只匹配了规格维度，日期维度没用上单据日期**。前端行情页接口已支持 `date` 参数但 UI 没有日期筛选。

### 6.2 目标逻辑

```
送货单确认入库
  └─ 对每条明细：行情匹配( quote_date = 送货单日期(当日无行情→向前最近一个有行情的日),
                              规格匹配: 名称+规格分层匹配[精确→归一模糊→范围→AI兜底] )
       └─ 网价写入送货单明细(新增 net_price 字段) + material_market_mappings 留痕
            └─ 销售单价自动预填 = 网价 + 上浮(默认 30, 明细可改)
```

- **导入时实时匹配**：送货单确认后触发（复用现有 `afterCommitMatch` 触发点，改为按单据日期）；
- **行情中心展示**：项目对比 tab 已展示每行「行情日期/市场价/价差」，天然承接；全量行情 tab 补一个日期筛选（接口现成）；
- **对账单导出**：直接读送货单明细上的 `net_price`（导入时已锁定当日网价，不随导出时点漂移——这点很重要，人工版对账单网价就是按发货当日的）。

## 八、需要你拍板的问题清单

1. **批次内供货单唯一性**：一个批次固定一张供货单，是否要在系统里强约束（现有代码允许多张）？存量多供货单批次如何处理？
2. **台账材料行展示粒度**：维持「按材料分组的多行 + 运输费用行」，还是简化为「材料合计一行（可展开）」？你说过不太关心具体材料，我倾向前者维持现状（已成型）。
3. **销售金额自动化的边界**：销售总金额 = 送货单明细合计自动填，是否允许人工改（参考文件存在手工调整痕迹）？建议：自动填 + 可改，改后标记「人工调整」。
4. **送货单无运费的场景**：强制必填的话，「供应商报价含运费」的批次（参考台账第 11 行兴泰「材料含运费」）填 0 并标记「含运」，还是允许显式 0？
5. **上浮 30**：固定默认值 30、按明细可改（模板公式 F=G-E 暗示可变）——确认默认 30、逐行可编辑？
6. **对账单导出粒度**：一次导出 = 一个日期范围一个 sheet？还是要一次选多个周期生成多 sheet 工作簿？累计值（累计供应量/累计支付）按项目滚动维护，确认口径（累计支付是否含本次）？
7. **网价缺口日的取价规则**：送货日期当天无行情（周末/爬虫缺失）→ 取「≤ 该日期的最近一个有行情日」，确认？
8. **发货单照片**：以原始送货单图片整张插入 K 列，还是只截取发货单部分（AI 无法可靠裁剪，建议整张）？取不到图片时写送货单编号降级，可以吗？
9. **对账单模板**：请提供空模板文件（.xls 或 .xlsx），我按第五节的骨架划分做动态填充。
10. **表头定义收敛**：台账表头目前前端 `buildGroups` 与后端 `writeHeader` 双份硬编码，本次是否顺手收敛为单一来源（后端下发或前端导出时传参）？建议收敛，但属于顺手项，可单独排期。
